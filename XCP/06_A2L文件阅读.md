# A2L 文件阅读

## A2L 解决什么问题

A2L（ASAM MCD-2 MC / ASAP2）是标定工具读取 ECU 变量和 XCP 配置的描述文件。它把地址、类型、换算、单位、事件和传输层参数组织起来。

可以把 A2L 看成三本字典的组合：

```text
通信字典：ECU 在哪条链路、使用什么 ID 和长度
内存字典：变量位于哪个地址、占多少字节、怎样访问
物理字典：原始整数怎样变成 V、A、rpm、km/h 等工程量
```

## 阅读顺序

拿到一个 A2L，建议按以下顺序看：

1. 找 `PROJECT`、`MODULE` 和版本信息。
2. 找 XCP 的 `IF_DATA`，确认 CAN ID、CTO/DTO 长度和能力。
3. 找 `MEASUREMENT`，确认测量变量地址、类型和换算。
4. 找 `CHARACTERISTIC`，确认标定参数和写权限。
5. 找 `COMPU_METHOD`，确认原始值到物理值的转换。
6. 找 `EVENT`、DAQ 和 ODT 相关描述。
7. 对照当前构建的 ELF/AXF/Map，检查地址是否匹配。

## MEASUREMENT 与 CHARACTERISTIC

- `MEASUREMENT` 通常描述测量变量，例如实时车速、电流和温度。
- `CHARACTERISTIC` 通常描述可标定的参数，例如限值、增益和曲线。

教学示意：

```text
MEASUREMENT VehicleSpeed
  地址：0x20001000
  类型：UWORD
  换算：Speed_0p1_kmh

CHARACTERISTIC MaxTorque
  地址：0x08040000 或工作页映射地址
  类型：SWORD
  换算：Torque_Nm
```

上述地址只是示意，不能当成真实项目地址。

## 常见对象之间如何引用

```text
MEASUREMENT / CHARACTERISTIC
        │ 引用
        ├── RECORD_LAYOUT：数据在内存中的布局
        ├── COMPU_METHOD：原始值与物理值的转换
        └── IF_DATA：XCP 和传输层专用配置
```

阅读一个对象时，不要只看对象名和地址，要沿着引用继续打开换算方法、单位和数据布局。数组、曲线和地图还会涉及维度、轴描述和记录布局，不能按单个标量处理。

## 标量、数组和地图

- **标量**：一个地址对应一个值，例如车速。
- **数组/曲线**：一段元素，需要元素个数和索引关系。
- **地图**：参数值依赖多个轴，要同时描述 X/Y 轴、维度、布局和插值规则。

工具显示二维地图时，显示的数据、轴和换算可能来自多个 A2L 对象。只验证地图首地址而不检查维度，容易出现数据错位。

## 换算方法的几种情况

### 线性换算

```text
物理值 = 原始值 × 系数 + 偏移
```

### 枚举换算

```text
0 -> OFF
1 -> ON
2 -> ERROR
```

### 查表换算

原始值通过查表映射到文本或物理值，不能用线性公式替代。

### 位域换算

一个字节可能包含多个信号，必须先按位掩码取出目标位，再进行符号和物理换算。

## 原始值和物理值

典型线性换算可以表示为：

```text
物理值 = 原始值 × 系数 + 偏移
```

例如原始值 `1234`，系数 `0.1`，偏移 `0`，则物理值为 `123.4 km/h`。还要检查符号位、端序、字节长度和无效值定义。

## 关键字段

| 字段 | 作用 |
| --- | --- |
| `ADDRESS` | ECU 内存地址 |
| `DATA_TYPE` | 数据类型和宽度 |
| `BIT_MASK` | 位域提取 |
| `BYTE_ORDER` | 多字节端序 |
| `COMPU_METHOD` | 原始值到物理值的换算 |
| `PHYS_UNIT` | 物理单位 |
| `ECU_ADDRESS_EXTENSION` | 地址扩展或地址空间 |
| `READ_ONLY` / 访问属性 | 是否允许写入 |
| `IF_DATA XCP` | XCP 传输和能力配置 |

## A2L 与程序版本一致性

变量地址来自编译和链接结果。更换编译选项、链接文件、编译器版本或程序版本后，旧 A2L 可能指向错误地址。工程中应建立软件版本、A2L、ELF/AXF 和标定数据的对应关系。

## 地址为什么会失效

常见原因包括：

1. 变量被优化掉或改为静态局部对象。
2. 链接文件改变，RAM/Flash 段起始地址变化。
3. 结构体增加字段，后续成员偏移变化。
4. 编译器、字节对齐或打包选项变化。
5. 工作页映射改变，但 A2L 仍使用旧页面地址。

因此 A2L 生成应尽量来自当前构建产物，并在发布时绑定软件版本、校验值和生成时间。

## A2L 与 XCP 的分工边界

A2L 可以告诉工具如何访问，但不能替 ECU 做权限检查。即使 A2L 标记为可写，Slave 仍应在运行时检查会话、保护状态、地址段和参数范围；即使 A2L 标记了 DAQ 事件，ECU 也必须实际触发该事件。

## 阅读检查清单

- A2L 的程序版本是否与 ECU 当前软件一致？
- CAN 命令 ID 和响应 ID 是否与实际总线一致？
- 地址是否属于当前内存映射？
- 数据类型、长度和端序是否正确？
- 换算系数、偏移和单位是否正确？
- 变量是否允许写入？
- DAQ 事件周期和 ODT 配置是否有足够资源？
