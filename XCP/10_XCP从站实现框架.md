# XCP 从站实现框架

## 典型软件分层

```text
CAN ISR / DMA
    ↓
传输适配层：收发队列、帧长度、CAN ID
    ↓
XCP 协议层：PID 分发、会话、错误响应
    ├── 内存访问适配器
    ├── DAQ 管理器
    ├── STIM 接收器
    ├── CAL/PAG 页面管理
    └── PGM 编程适配器
    ↓
应用适配层：变量快照、事件触发、参数提交
```

传输层不应决定车速或转矩的业务含义；应用层也不应直接拼 XCP PID 或修改协议状态。

## 任务和中断职责

一个可行的实时边界是：

- CAN ISR/DMA：尽快接收帧，写入环形队列，避免解析复杂命令。
- XCP 任务：解析 CTO、检查状态、调用内存/DAQ/STIM 适配器。
- 控制任务：在确定的 Event Channel 点触发 DAQ 采样或提交 STIM 快照。
- 发送任务或驱动：把响应和 DTO 交给 CAN 发送队列。

任务周期、优先级和队列深度必须结合实际 MCU、CAN 负载和控制周期确定，不能从示例直接复制。

## 内存访问接口

建议把协议层和地址安全策略分开：

```c
Xcp_Status Xcp_MemoryRead(uint32_t address,
                          uint8_t extension,
                          uint8_t *buffer,
                          uint32_t length);
```

适配器应检查空指针、长度、地址段、权限、对齐和当前 ECU 状态。Flash 写入还要返回擦除忙、校验失败、掉电中断等具体原因。

## DAQ 事件接口

应用任务不需要知道 ODT 的内部链表或 CAN ID，只提供类似下面的意图接口：

```c
void Xcp_DaqEvent(uint16_t event_id);
```

XCP 模块收到事件后，根据已激活配置读取变量、生成 DTO 并提交发送。事件接口不能长时间阻塞控制任务。

## STIM 快照接口

STIM 接收层先验证帧长度、序号、时间窗口和数据范围，再把完整数据发布给应用。应用读取的是稳定快照，而不是 CAN 接收缓冲区本身。

```text
接收缓存 -> 校验 -> 双缓冲切换 -> 应用读取
```

## 资源管理

启动 DAQ 前需要确认 ODT、发送缓存和事件绑定资源。资源不足时应返回明确错误，不应静默覆盖其他 DAQ 配置。停止或断开连接时应释放或复位运行时资源。

## 断线和恢复

断线处理至少包括：

1. 停止主动 DTO 和 STIM 使用。
2. 清理未完成的块传输和发送队列。
3. 保留或清除 DAQ 配置，按项目策略决定。
4. 使临时标定参数和页面状态进入定义好的状态。
5. 重新 CONNECT 后重新检查能力，不假定旧会话仍有效。

## 代码审查重点

- 协议状态是否只由 XCP 模块修改？
- 地址访问是否经过白名单和边界检查？
- DAQ 事件是否可能与配置切换并发？
- DTO 和 STIM 缓冲区是否存在生命周期或半更新问题？
- 发送队列满时是否有统计和降级？
- Flash 写入是否有完整性校验和掉电恢复？
