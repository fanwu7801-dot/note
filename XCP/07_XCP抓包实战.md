# XCP 抓包实战

## 准备材料

- CAN 接口和抓包工具；
- 当前 ECU 软件版本；
- 与软件匹配的 A2L；
- CAN 总线速率和 XCP ID 配置；
- 明确的测试变量和安全的 RAM 参数。

涉及写 RAM、Flash 或 Seed & Key 时，应按项目授权和测试规范操作。

## 抓包步骤

### 1. 先记录静态信息

```text
软件版本：
A2L 版本：
CAN 速率：
命令接收 ID：
响应/DAQ ID：
目标变量：
```

### 2. 识别连接阶段

观察是否依次出现 CONNECT、能力查询、状态查询和权限解锁。把每一条命令与响应配对，记录错误响应和等待时间。

### 3. 识别单次读取

重点关注：

```text
设置 MTA 地址
       ↓
UPLOAD 请求
       ↓
返回原始字节
       ↓
A2L 换算为物理值
```

### 4. 识别 DAQ

配置阶段通常会出现 DAQ List、ODT 和 ODT Entry 相关操作；启动后，ECU 应在事件周期主动发送带 DAQ PID 的 DTO。停止后应停止对应 DTO。

| 0 ms | M->E | 教学假设 | 教学假设 | CONNECT | 建立会话 |
| ... | ... | ... | ... | ... | ... |

不要只保存截图，最好同时保存原始日志、A2L 版本、工具配置和测试条件。

## 现象到原因

| 现象 | 优先检查 |
| --- | --- |
| 无响应 | CAN 速率、XCP ID、ECU 是否启用、总线物理层 |
| CONNECT 成功但读变量失败 | A2L 地址、权限、内存段、地址扩展 |
| 单次读取正确，DAQ 错误 | ODT Entry、事件触发、DTO PID、端序 |
| 波形周期不对 | Event Channel 周期、任务抖动、发送队列 |
| 数值很大或负数异常 | 类型、符号位、端序、换算方法 |
| 停止 DAQ 后仍有数据 | Stop 流程、缓存排空、其他 DAQ List |

## 证据边界

抓包能证明总线上的命令、响应和周期，不能单独证明 ECU 内部变量计算正确，也不能证明 Flash 参数已经安全保存。需要把源码、A2L、抓包和台架现象关联起来。

## 推荐输出

一次完整分析至少包含：

1. 软件、A2L 和工具版本。
2. XCP CAN ID 和总线配置。
3. 命令响应时序。
4. 目标变量地址、类型和换算。
5. DAQ 的事件周期、ODT 布局和实际 DTO 周期。
6. 错误响应、丢帧和恢复行为。
