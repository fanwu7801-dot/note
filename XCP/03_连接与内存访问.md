# 连接与内存访问

## 典型连接流程

```text
CONNECT
  ↓
GET_STATUS
  ↓
GET_COMM_MODE_INFO / GET_ID
  ↓
查询 DAQ、STIM、PGM 等能力
  ↓
必要时执行 Seed & Key 解锁
  ↓
开始内存访问或 DAQ 配置
```

工具应根据响应判断 ECU 的实际能力，不应假设所有命令都支持。

## 会话状态机

可以先用下面的抽象状态理解从站：

```text
DISCONNECTED
    │ CONNECT 成功
    ▼
CONNECTED_LOCKED
    │ 解锁成功
    ▼
CONNECTED_UNLOCKED
    │ 允许配置 DAQ、读写或编程
    ▼
ACTIVE
```

实际协议实现可能有更多状态。重点是：连接状态、保护资源状态、DAQ 运行状态和 Flash 编程状态应分别维护，不能用一个布尔变量代替全部条件。

## CONNECT 响应要读什么

至少记录以下能力：

- 支持的资源位：CAL/PAG、DAQ、STIM、PGM；
- 最大 CTO 和 DTO 长度；
- 地址粒度和字节序；
- 是否支持时间戳、事件和块传输；
- 是否需要 Seed & Key 才能访问特定资源。

这些字段决定后续命令能否执行，也决定工具如何分配 ODT 和传输缓冲区。

## MTA：内存传输地址

`MTA` 是 XCP 内部用于内存传输的地址指针。典型操作是先设置 MTA，再执行上传或下载。

```text
SET_MTA(address)
       ↓
UPLOAD(length)      ECU -> Master
DOWNLOAD(data)      Master -> ECU
```

地址除了数值本身，还可能需要 Address Extension 来表示不同的地址空间或内存段。

## UPLOAD 读取示例

教学假设变量位于 `0x20001000`，长度为 2 字节：

```text
1. Master：设置 MTA = 0x20001000
2. Master：请求 UPLOAD，长度 = 2
3. ECU：检查地址范围和读取权限
4. ECU：返回两个原始字节
5. Master：按照 A2L 类型和换算显示物理值

## 读取一个 32 位变量的思考过程

假设 A2L 说明变量是小端 `uint32`，地址为 `0x20001000`，长度为 4 字节。
工具收到四个原始字节后，需要按端序组成整数，再套用 `COMPU_METHOD`。
如果只看抓包中的十六进制，不知道端序和换算，就不能得出可靠的物理值。
```

## DOWNLOAD 写入示例

```text
1. Master：设置 MTA = 参数地址
2. Master：发送 DOWNLOAD 和原始数据
3. ECU：检查地址、长度、对齐和写权限
4. ECU：写入 RAM 或允许的内存页
5. ECU：返回正响应或错误响应

## 块传输与分段

当数据超过一个 CTO 能承载的长度时，工具和从站可能使用块上传、块下载或多次短传输。实现需要维护：当前块序号、剩余长度、超时计数和取消操作。收到重复块、跳号块或长度超过缓冲区时，应停止当前传输并返回明确错误。
```

写 Flash 还要增加擦除、编程、校验、掉电保护和恢复策略，不能把 RAM 写入流程直接当成量产刷写方案。

## 必须检查的异常

| 异常 | 处理重点 |
| --- | --- |
| 未连接 | 拒绝需要会话的命令 |
| 未解锁 | 拒绝受保护资源访问 |
| 地址越界 | 返回内存访问错误，不读写越界地址 |
| 长度过大 | 按 CTO/DTO 和实现上限拒绝或分段 |
| 非法对齐 | 按 MCU 访问限制返回错误 |
| Flash 忙 | 返回资源占用或状态不允许 |
| 校验失败 | 不提交参数，报告数据错误 |

## 工程定位方法

在源码中建议按以下顺序搜索：

1. 命令码枚举和 CTO 分发函数。
2. `SET_MTA`、`UPLOAD`、`DOWNLOAD` 的处理函数。
3. 内存访问回调或地址段表。
4. CAN 接收回调、发送队列和 XCP 周期任务。
5. A2L 生成脚本或链接文件中的变量地址。

## 一个安全的内存访问适配器

协议层不应直接把任意地址转换成 C 指针后读写。建议由适配层提供：

```text
Xcp_MemoryRead(address, extension, buffer, length)
Xcp_MemoryWrite(address, extension, buffer, length)
```

适配层负责地址段白名单、长度上限、对齐、读写权限和 Flash 特殊流程。协议层只处理命令状态和响应编码，应用层提供允许公开的变量或内存段。
