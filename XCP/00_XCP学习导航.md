# XCP 学习导航

## 一句话理解

XCP 让标定工具能够通过通信链路访问 ECU 的内部内存。工具负责提出访问和采集需求，ECU 中的 XCP Slave 负责检查权限、读写内存并组织数据。

学习 XCP 时不要把它只看成一组命令字节。完整问题是：工具怎样描述变量，ECU 怎样确认地址合法，变量在什么时刻被采样，数据怎样排队发送，出现超时或权限不足时如何降级。

```text
标定工具（Master）
        │ XCP 命令和数据
        ▼
传输层（CAN / Ethernet / FlexRay ...）
        ▼
ECU XCP Slave
        │
        ├── 访问 RAM/Flash
        ├── 触发 DAQ 采样
        └── 接入应用变量和事件
```

## XCP 能做什么

| 能力 | 方向 | 典型用途 |
| --- | --- | --- |
| 内存读取 | ECU -> Master | 查看车速、温度、状态机状态 |
| 内存写入 | Master -> ECU | 修改 RAM 标定参数 |
| DAQ | ECU -> Master | 按任务周期同步采集多个变量 |
| STIM | Master -> ECU | 给控制算法注入外部计算值 |
| PAG/CAL | Master <-> ECU | 工作页、参考页和参数标定 |
| PGM | Master -> ECU | 开发阶段的 ECU 编程 |

## XCP 与 UDS 的边界

XCP 面向开发测量和标定，访问对象通常是变量地址；UDS 面向诊断、维修和量产刷写，访问对象通常是诊断服务、DID、DTC 或 Routine。两者都可能涉及刷写，但会话管理、数据组织和工具链不同。

## 学习时要建立的四层模型

1. **应用变量层**：变量在控制任务中被计算或更新。
2. **XCP 协议层**：解析命令、维护会话、组织 CTO/DTO。
3. **传输层**：把 XCP 包封装到 CAN、UDP 或其他链路。
4. **描述文件层**：A2L 告诉工具变量地址、类型、换算和事件。

## 每章都要回答的四个问题

- 工具发出了什么请求？
- ECU 的哪个模块接收并处理？
- 数据从哪里读出或写入？
- 工具如何知道这个原始值代表什么物理量？

## 三条主线

### 主线一：连接和内存访问

```text
建立会话 -> 查询能力 -> 设置 MTA -> UPLOAD/DOWNLOAD -> 关闭会话
```

这条主线适合先验证链路、地址和权限。它是“请求一次、响应一次”的同步访问。

### 主线二：DAQ 测量

```text
选择变量 -> 组织 ODT -> 绑定事件 -> 启动 DAQ -> ECU 主动发送 DTO
```

它适合观察变量随时间的变化，关键是采样点和发送点是否符合控制任务时序。

### 主线三：STIM 激励

```text
工具准备输入 -> 发送 STIM DTO -> ECU 在事件点接收 -> 算法读取
```

它适合外部算法、旁路和快速原型，关键是数据新鲜度、超时和恢复策略。

## 推荐学习方法

每学一个命令，都记录四项：请求方向、前置状态、输入字段、成功或错误后的状态变化。每学一个变量，都同时记录地址、长度、类型、端序、换算和有效范围。

## 先掌握的术语

`Master`、`Slave`、`CTO`、`DTO`、`DAQ`、`ODT`、`ODT Entry`、`Event Channel`、`A2L`、`MTA`、`CAL`、`PAG`、`PGM`、`Seed & Key`。

## 练习入口

读完基础章节后，拿一个 `uint16_t` 变量完成：连接 ECU、单次读取、配置 10 ms DAQ、观察连续 DTO，再修改一个 RAM 参数。
