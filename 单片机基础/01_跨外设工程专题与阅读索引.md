# 跨外设工程专题与阅读索引

本页把17篇笔记连接起来。单独知道一个寄存器的作用，只能完成局部配置；
设计系统还需要同时约束时间、数据、电气、资源和恢复行为。

## 一、先按三个深度读同一篇

第一层用原理图和具体数值建立直觉；第二层阅读“深入学习”，把寄存器机制、公式条件和失效路径讲清；第三层按实验问题设计观察与验证。
无法现场验证的结论，停留在理论推导或资料核对层，不把它写成开发板已经实现。

| 主题 | 深入时应能回答的问题 |
|---|---|
| MCU与启动 | 地址、值、物理存储区、启动映射和VTOR如何区分？ |
| 构建与调试 | 符号怎样进入最终镜像，map如何证明布局？ |
| GPIO | 四位配置、读改写竞争、电气阈值和负载怎样相连？ |
| 中断 | 请求源、屏蔽、优先级、入栈与任务交接如何相连？ |
| ADC/DMA | 建立时间、量化、混叠与缓冲所有权怎样取舍？ |
| 定时器输出 | 频率、分辨率、中心对齐和同步提交怎样推导？ |
| 输入捕获 | 回绕范围、量化误差和过捕获怎样限制测量？ |
| USART | 位时间、硬件流水线、缓存和组包怎样闭环？ |
| 无线模块 | 本地接口、空口网络和业务确认怎样分层？ |
| I2C/SPI | 电气/采样边沿、事务与设备寄存器怎样分层？ |
| 存储 | 编程限制、磨损和掉电恢复怎样一起设计？ |
| RTC/低功耗 | 绝对时间、单调时间、能量与恢复现场怎样区分？ |
| FreeRTOS | 周期、栈、阻塞、所有权与截止时间怎样预算？ |

## 二、统一看待时钟、时间戳与超时

系统至少有CPU/总线时钟、定时器计数、RTOS Tick、RTC绝对时间、传感器内部采样时间等不同基准。
一个数值叫timestamp，并不表示它们可以直接相减。要先说明单位、纪元、频率误差、回绕宽度和是否单调。

RTC用于日历和日志时刻，可能被校时；超时应优先用单调基准；定时器适合微秒级硬件事件；Tick负责调度尺度的等待。
时间转换应尽量保留足够宽度，避免先做整数除法丢失小量，再乘回去制造误差。

无符号差值可以帮助处理回绕，但需满足约定的最大观测间隔。只有“用了无符号类型”不自动证明跨任意长时间的比较都正确。
当输入捕获可能跨多个模周期时，还需溢出扩展或受控范围。

## 三、固定速率系统要分别预算周期、吞吐和延迟

周期回答多久做一次，吞吐回答单位时间能处理多少数据，延迟回答某个输入到结果要等多久。
扩大缓冲可能改善短时吞吐承受能力，却增加成块交付延迟；提高优先级可能降低等待，却不能突破SPI时钟或Flash内部写入时间。

例：ADC每毫秒一轮，缓冲32轮才交付，虽然采样率1 kHz，业务最晚得到一块新数据需要约32 ms尺度。
如果控制要求2 ms内使用样本，应该调整交付粒度/路径，而不是只把控制任务优先级调高。

## 四、画一条“采样到输出”的完整时间链

```text
定时器触发
  → ADC采样窗口与转换
  → DMA搬运并形成可读块
  → ISR记录/通知
  → 任务获得CPU
  → 校验、换算与控制
  → 输出寄存器预装载
  → 下一个有效更新边界
  → GPIO/驱动器真实动作
```

总响应包含每一段以及排队和相位等待。若CCR只在周期边界装载，即使控制计算只耗50 μs，也可能额外等待接近一个PWM周期。
同步设计可以使采样和装载关系确定；盲目缩短计算时间不一定是总延迟最大的改进点。

## 五、每一块数据都问四个问题

谁写？谁读？什么时候稳定？到什么时候仍有效？
ADC循环DMA缓冲、串口环形缓冲、RTOS指针消息和Flash记录都需要这些答案。
它们分别涉及覆盖窗口、消费速率、对象生命周期与提交状态，不能只用一个“全局数组”概括。

业务快照宜说明值、单位、采集时间、有效性和质量/错误原因。
超时后保留最后值可以用于界面显示，但若用于控制，必须同时传播“已过期”，否则看似平滑的值会掩盖传感器已离线。

## 六、配置、上下文、数据、操作分别放在哪里

| 类别 | 例子 | 访问原则 |
|---|---|---|
| cfg | 时钟参数、通道序列、超时、量程和容量 | 受控配置，变更需校验 |
| ctx | DMA索引、组包阶段、锁/任务句柄、重试状态 | 拥有模块私有维护 |
| data | 温度、转速、输出反馈及时间/质量 | 通过一致快照发布 |
| ops | 初始化、启停、保存请求、获取结果 | 表达意图并返回明确结果 |

四元组是检查边界的方法，不要求把所有字段硬塞进同一个巨大结构体。
如果应用层为了点灯直接改DMA索引，或者驱动为了“业务成功”自行吞掉超时，就已经跨越了需要重新审查的职责边界。

## 七、错误不应该只有一个真假值

空指针/范围错误表示调用不合法；总线忙可能稍后重试；通信超时可能意味着结果未知；校验失败表示收到的数据不可接受；
设备未初始化和当前状态不允许则提示执行前提不满足。

相同“失败”外观可能需要完全不同恢复。RFID扣款超时不能直接重复执行，ADC读取超时不能发布旧缓存为本次数据，Flash未提交记录不能被当成最新配置。
重试次数与总时间都应有界，恢复动作本身也要保留诊断信息。

## 八、原子性有多个层次

单次对齐字访问可原子，不等于`counter++`原子；BSRR单次位操作不等于一个脚可以被多个业务模块随意竞争；
CRC正确不等于存储事务原子；无线链路应答不等于业务恰好执行一次。

保护方案要对准层次：短临界区保护小快照，队列处理交接，互斥锁保护资源，序号识别请求，提交记录处理掉电恢复。
没有一种关键字或API能同时解决全部层次。

## 九、低功耗会跨越原本独立的外设边界

进入Stop前，串口可能仍在移出最后一个字节、Flash可能内部忙、DMA可能正在形成一块采样。
CPU当前没有业务不代表所有硬件都允许停时钟。
唤醒后又需要先恢复时钟，再恢复依赖它的波特率、采样和输出，并更新数据是否仍新鲜。

电源管理因此应集中协调约束：哪个模块持有“保持运行”请求、谁能阻止深睡、恢复失败如何降级。
Standby按复位路径恢复时，还要区分持久配置、后备标记和已经丢失的普通SRAM现场。

## 十、一个综合练习：三路采样、无线显示与掉电参数

设三路ADC每路1 ksample/s、16位结果，原始负载为6 kB/s；若蓝牙模块本地串口仅9600、8N1，其理想连续负载上限约960 B/s，不能持续原样转发全部样本。
需要选择降采样、聚合统计、事件上报或更高接口速率，并计算帧开销与突发缓存。

如果每100 ms发送每路平均值，通信负载显著下降，但这份数据显示平均窗口，不是最近一次瞬时采样。
控制若仍要毫秒级响应，就应在本地用适合的实时路径处理，而不是等待无线平均值再反馈。

参数变更先在RAM中校验，按受控策略持久化；Flash操作要避开关键实时窗口或采用已经验证的安排。
系统重启时恢复最近提交配置，时间未可信时单独标记，不把零时间戳伪装成已校时。

## 十一、如何给出有边界的验证结论

先说明条件：芯片、板卡、固件版本、时钟、负载与仪器；再写观察值和允许范围；最后指出未覆盖条件。
“构建成功”与“示波器上输出正确”是不同证据，“台架通过”也不自动覆盖所有车辆、电源和温度条件。

对学习笔记而言，公式复算、寄存器语义核对和图示检查属于资料层；本次没有创建可运行固件或进行上板验证。
真实工程采用示例前，需要用实际电路、配置和测试约束替换教学假设。

## 十二、资料阅读顺序

先从对应课件获得课程范围，再读数据手册确认具体型号资源与电气条件，读参考手册理解寄存器机制，再读编程/应用说明处理特殊时序。
发现芯片异常或版本相关问题时，再查对应器件勘误；驱动库源码帮助理解软件封装，却不能替代电气和硬件机制的原始定义。
